# Технический стек

**Статус:** предварительные варианты для оценки. Выбор библиотек, провайдера LLM и способа развёртывания не утверждён; код ещё не реализован.

| Задача | Кандидат / подход | Что проверить в спринте 1 |
| --- | --- | --- |
| Язык прототипа | Python | Удобство интеграции OCR, обработки файлов и проверки результатов |
| Приём документов | Небольшой локальный API или сценарий командной строки | Нужен ли интерфейс на первом этапе |
| Извлечение текста | OCR движок, выбранный по результатам сравнения | Качество на согласованных типах документов, русский язык, координаты фрагментов |
| Извлечение полей | LLM со структурированным ответом | Точность полей, ссылки на исходный текст, поведение при недостатке данных |
| Проверки | Явные правила в коде | Обязательные поля, формат, согласованность значений |
| Хранение | Локальные тестовые файлы без реальных данных | Нужна ли база данных после уточнения сценария |
| Автоматическая проверка | Небольшой набор синтетических примеров | Повторяемость сравнения OCR и извлечения полей |

Список не означает, что перечисленные компоненты уже установлены или интегрированы. Версии, лицензии, стоимость и условия передачи данных следует зафиксировать перед выбором конкретных инструментов.

## Критерии выбора

1. Качество на согласованных образцах документов, включая плохие сканы.
2. Возможность проследить вывод до фрагмента исходного документа.
3. Работа с русским текстом и нужными форматами файлов.
4. Ограничения по данным, стоимости, скорости и лицензиям.
5. Простота воспроизводимого запуска для двух участников команды.
