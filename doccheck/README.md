# DocFlow — локальная проверка документов

Сайт для проверки документов через локальную Qwen в LM Studio. Модель определяет вид документа по содержанию и выбирает план проверки. Для остальных документов применяется общий план. Фронтенд: HTML, CSS и JavaScript. Бэкенд: Python, FastAPI, SQLite. При локальной работе документы не передаются в облако; при удалённой работе через Cloudflare Tunnel данные проходят через инфраструктуру Cloudflare.

## Первый запуск на Windows

Установите Python 3.12 и LM Studio. Выполните команды в PowerShell из папки `doccheck`:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для OCR подготовьте локальные веса по инструкции ниже.

## Запуск сайта

1. Откройте LM Studio. Загрузите `qwen3.5-4b` с поддержкой изображений и включите локальный сервер на порту 1234.
2. Дважды нажмите `START.cmd` в папке `doccheck`.
3. Откроется `http://localhost:8000`.
4. Загрузите документ и нажмите «Проверить документ». Переключаться между разделами можно, пока идёт обработка.
5. Для остановки сервера сайта нажмите `STOP.cmd`. LM Studio останавливается отдельно. Если прервать проверку, после перезапуска она будет помечена как прерванная и её можно повторить.

После перезагрузки компьютера повторите первые два шага. Автозапуск не настроен. Запуск сайта не загружает новые модели и не меняет настройки LM Studio.

## Что реализовано

- Локальный OCR для изображений и страниц PDF без текстового слоя. Qwen получает распознанный текст вместе с изображением и сверяет их при заполнении полей.

### Языковые файлы OCR

Основной OCR при наличии локальных весов — PaddleOCR на CPU с моделями `PP-OCRv5_mobile_det` и `eslav_PP-OCRv5_mobile_rec`. Для переноса на другой ПК создайте окружение `tools/paddleocr-env` на Python 3.12 с `paddleocr==3.6.0` и `paddlepaddle==3.3.0`. Положите `inference.json`, `inference.yml` и `inference.pdiparams` в отдельную папку каждой модели в `tools/paddleocr-models/`. При сбое PaddleOCR или пустом результате на странице используется Tesseract. Отчёт показывает фактически использованный движок.

Положите `rus.traineddata` и `eng.traineddata` из [tessdata_best](https://github.com/tesseract-ocr/tessdata_best/tree/4.1.0) в `tools/tessdata-best/`. Если этой пары файлов нет, DocFlow ищет [tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast/tree/4.1.0) в `tools/tessdata/`. Через `TESSDATA_PREFIX` можно задать конкретную папку. При отсутствии русского файла или при сбое OCR Qwen проверяет изображение напрямую. Для подписи используется изображение.

### Проверка документов

- Загрузка JPG, PNG, WEBP, PDF и DOCX, не более 15 МБ.
- Все страницы PDF анализируются как изображения; максимум три страницы на документ. Для DOCX извлекается текст, включая таблицы; вложенные картинки и рукописные подписи в DOCX не анализируются.
- Ограничение текстового содержимого — 11 000 символов; превышение возвращает понятную ошибку, документ не обрезается незаметно.
- Очередь до пяти документов, один запрос к Qwen одновременно. Тайм-аут ответа модели — пять минут.
- Планы для заявлений, договоров, счетов, актов, справок, приказов и писем. Отчёт показывает поля выбранного плана, цитаты, возможные противоречия и неразборчивые фрагменты.
- Отчёт рядом с оригиналом, история последних 200 записей, повторная проверка, удаление оригинала с отчётом, скачивание TXT или JSON.
- Сообщения о недоступной модели, ошибках файлов и прерванных проверках.

Сверяйте определённый вид, значения и цитаты с оригиналом. Для планов с подписью отчёт указывает, обнаружила ли модель росчерк на изображении. Подлинность подписи подтверждает человек.

## Где хранятся данные

`data/uploads/` — оригиналы, `data/history.sqlite3` — текст и отчёты, `data/server*.log` — журналы сервера. История сохраняется после закрытия браузера. Резервная копия — копия папки `data` при остановленном сервере. Журналы LM Studio находятся отдельно; удаление документа на сайте их не очищает.

## Домен и доступ с других устройств

### Временный доступ через интернет

Для тестирования существует `START_REMOTE.cmd`: он запускает сайт и Cloudflare Quick Tunnel, выдаёт временный адрес HTTPS, логин `doccheck` и новый случайный пароль. Откройте этот адрес на другом устройстве и введите логин с паролем. На время удалённого режима пароль нужен также для локальной версии сайта. `STOP_REMOTE.cmd` отключает внешний доступ, не останавливая сайт или LM Studio. Для нового адреса и пароля остановите текущий туннель и запустите удалённый режим снова. Пароль хранится в `data/remote.json` и удаляется при остановке. Не публикуйте пароль или эту папку.

Для запуска туннеля скачайте Windows-версию из [официальных релизов cloudflared](https://github.com/cloudflare/cloudflared/releases) и сохраните её как `tools/cloudflared.exe`. `START_PUBLIC.cmd` запускает демонстрационный режим без пароля с отдельной папкой `public-data/`. Используйте в нём вымышленные документы.

Quick Tunnel предназначен для тестов: у него нет гарантии доступности, адрес меняется при каждом запуске, он работает, пока работает процесс и включён компьютер. Cloudflare выступает посредником: запросы и документы проходят через его сервис, хотя модель обрабатывает их на вашем ПК. Все пользователи с паролем видят общую историю, имеют возможность просматривать, загружать и удалять документы; отдельных аккаунтов и изоляции данных нет. Используйте только учебные или обезличенные документы. Не считайте этот режим готовым решением для настоящих кадровых документов. Для постоянного сервиса нужны индивидуальные аккаунты, разграничение прав, ограничение попыток входа, аудит, резервное копирование и стабильный защищённый хостинг.

На время работы туннеля приложение просит Windows не переводить компьютер в автоматический сон. Отключение экрана возможно. Ручной сон, выключение или перезагрузка всё равно прервут доступ; запрос снимается после остановки туннеля.

Домен для работы на этом ПК не нужен. `localhost` всегда означает компьютер, на котором открыт браузер: эта ссылка не откроет ваш сервер у другого человека.

Для доступа в одной домашней сети домен также не нужен; используют локальный IP компьютера. Текущая версия намеренно слушает только `127.0.0.1`, проверяет адрес и источник запросов. Для сетевой версии нужно добавить вход пользователей, изменить сетевые настройки приложения и разрешить входящий порт сайта в Windows. Простого изменения адреса запуска недостаточно. LM Studio должна оставаться доступной только бэкенду.

Для доступа из интернета нужны защищённое соединение HTTPS, авторизация и способ добраться до сервера — например, частная VPN или настроенный туннель. При публичном размещении также нужны ограничения запросов, аудит доступа и политика хранения документов. Домен удобен для постоянного адреса, но не заменяет эти настройки. Не открывайте порт LM Studio в интернет.

Компьютер должен быть включён, не спать, а сервер сайта и LM Studio — работать. Видеопамять делится с другими программами. Одновременные посетители будут ждать очередь. Публичное размещение и многопользовательский режим в эту локальную версию не входят.

## Для разработчика

Запуск вручную из этой папки: `.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000`.

Переменные окружения: `LM_STUDIO_URL` (по умолчанию `http://127.0.0.1:1234`, разрешены только адреса этого компьютера), `LM_STUDIO_MODEL` (`qwen3.5-4b`), `LM_STUDIO_API_KEY` (если в LM Studio включена авторизация), `DOCCHECK_DATA_DIR` (другая папка данных). После изменения требуется перезапуск. Секреты не передаются в браузер.

Проверки: `.venv\Scripts\python.exe -m pytest tests -q`. Для тестов потребуется `pytest`; тестовые данные хранятся отдельно от рабочей истории, вызов Qwen подменяется только внутри автоматических тестов.

Протокол интеграции: [LM Studio Chat Completions](https://lmstudio.ai/docs/developer/openai-compat/chat-completions), [структурированный ответ](https://lmstudio.ai/docs/developer/openai-compat/structured-output).
